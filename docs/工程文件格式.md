# 工程文件格式设计（`.aiproj` v1）

> 目标：一个工程文件要能**完整还原**出 `demo/feasibility/demo.nsi`。
> 这样脚本生成器写完后，可以拿 demo 工程做「生成结果逐字对比」，不用靠肉眼检查。

配套示例：`demo/feasibility/demo.aiproj` —— 可用的完整工程文件，
它对应的正是已经验证通过的 `demo/feasibility/demo.nsi`。

---

## 一、文件约定

`.aiproj` 现在是一个**单文件容器**（ZIP，扩展名保持不变），像 PSD 一样：
一个文件里装着工程的全部内容，发给别人、备份、搬移都只搬它。

```
我的软件.aiproj            ← 本质是 zip，双击可关联到本软件直接打开
├── project.json           ← 下面这份 JSON（UTF-8 不带 BOM）
├── assets/                ← 图标、位图
├── payload/               ← 要打包的文件
└── （用户自己放的其它文件，如 docs/）
```

读取时的规则：

| 项目 | 约定 |
|---|---|
| 扩展名 | `.aiproj`（App Installer Project） |
| 两种形态 | **容器**（文件头是 `PK`，zip）和**老的文件夹工程**（文件头是 `{`，纯 JSON）。靠文件头自动识别 |
| 运行时 | 容器会先解到一份**缓存目录**（默认软件目录下的 `data\work\`）再干活；保存时重新打包（`build/` 等中间产物不进容器） |
| `project.json` / 老 JSON 编码 | **UTF-8 不带 BOM**（JSON 规范要求） |
| 路径基准 | 所有相对路径**以工程根目录为基准**（容器模式就是缓存目录） |
| 生成物 | 输出的 `.nsi` 统一存 **UTF-8 带 BOM**（NSIS 的硬性要求） |

## 二、顶层结构

```jsonc
{
  "formatVersion": 1,
  "generator":   { ... },  // 可选，写出此文件的软件信息
  "project":     { ... },  // 工程元数据
  "app":         { ... },  // 这是什么软件：名称/版本/版权/图标
  "files":       { ... },  // 打包什么
  "install":     { ... },  // 怎么装：权限、路径
  "interface":   { ... },  // 安装向导各页面的文案与图片
  "shortcuts":   { ... },  // 快捷方式
  "uninstall":   { ... },  // 怎么卸
  "build":       { ... }   // 输出设置
}
```

分包理由：`app` + `files` 是「打包什么」，`install` + `interface` + `shortcuts` + `uninstall` 是「怎么装」。
将来做 GUI 时，这两组正好对应向导的前后两个阶段。

`formatVersion` 读到比本程序更高的值时，应提示「此工程由更新版本创建」并拒绝打开，不要猜。

## 三、几个关键设计决策

### 3.1 「显示名」和「目录名」分开

`app.name` 是给用户看的（`我的小工具`），`app.dirName` 是装到磁盘上的文件夹名（`MyApp`）。
两者默认相同，但强烈建议中文软件把 `dirName` 设成英文——中文路径在命令行、日志、脚本里很容易出问题。

`app.registryKey` 默认等于 `dirName`，作为卸载项和「记住上次安装位置」的键。

### 3.2 安装模式只在「打包」这一步选

- 真正决定产出的是 `build.modes`（第 6 步的多选）：勾一个就出一个包，勾两个就两个包，
  文件名自动加 `-PerMachine` / `-PerUser` 后缀，避免互相覆盖；
- `install.mode` 保留为「默认 / 兜底模式」：**只在 `build.modes` 为空时给预览用**。
  界面上不再单独提供「安装模式」单选 —— 免得一处选、一处又勾，还容易和预览对不上；
- 实际安装路径在 `install.defaultDir` 留空时由**编译模式**决定：
  perMachine → `$PROGRAMFILES64`，perUser → `$LOCALAPPDATA\Programs`。

| | `perMachine` | `perUser` |
|---|---|---|
| 安装位置 | `Program Files` | `%LOCALAPPDATA%\Programs` |
| 权限 | **需要管理员（弹 UAC）** | 免提权，双击就装 |
| 快捷方式 | 所有用户可见 | 仅当前用户 |
| 注册表 | `HKLM` | `HKCU` |

### 3.3 页面「显示与否」由内容决定，不由单独的开关堆出来

为了不让用户配出一堆矛盾组合，设计器要按下面的规则**自动**决定页面：

| 页面 | 显示条件 |
|---|---|
| 欢迎页 | `interface.welcome.enabled` |
| 许可协议页 | `interface.license.enabled && license.file 存在` |
| 更新日志页 | `interface.changelog.enabled && changelog.file 存在` |
| 安装位置页 | `install.allowChangeDir` |
| 安装选项页 | `optionsPage.enabled && (快捷键至少有一个 enabled)` |
| 完成页 | 永远显示 |

### 3.4 字段速查

`*` = 必填。未列的键一律视为非法，读取时报错而不是忽略。

```text
app                # 应用基本信息
├ name*            显示名，出现在快捷方式、控制面板、欢迎页
├ dirName          安装目录名，默认 = name（中文软件建议设成英文）
├ version*         显示版本 1.0.0
├ fileVersion      exe 属性里的 a.b.c.d，默认由 version 补齐
├ publisher        公司 / 作者
├ copyright        版权声明
├ homepage         官网 URL
├ description      exe 属性里的一句话描述
├ registryKey      注册表 / 卸载项标识，默认 = dirName
│                  可以含中文；会自动把 \ / $ 换成 _。留空即按目录名派生
├ icon             .ico 路径，安装包图标 + 快捷方式图标
├ mainExe          主程序（相对安装目录），默认自动识别
└ mainExeArgs      启动参数

files              # 打包什么
└ items[]          { type: "file"|"folder", source, dest, keepFolder, include[], exclude[] }
                   dest 是条目在安装目录里的位置，"." 表示安装根目录
                   file   -> 安装到  dest\<文件名>
                   folder -> keepFolder=true（默认）：安装到 dest\<文件夹名>\...
                             keepFolder=false：只把内容放到 dest\...（不保留文件夹名）
                   keepFolder 只对 folder 有意义；旧工程没有该字段时按 true 处理
                   include 为空 = 全部包含；exclude 为空 = 不排除
                   通配符按 fnmatch 处理，"**/*.pdb" 也能匹配根目录下的 x.pdb

install            # 怎么装
├ mode                 "perMachine" | "perUser"
├ defaultDir           默认安装路径模板；null = 按模式自动
├ allowChangeDir       是否显示「安装位置」页
├ rememberLastDir      是否记住上次安装位置
└ estimatedSizeAuto    是否写入「占用空间」

interface          # 安装向导界面
├ language             "zh-CN"
├ brandingText         底部状态栏文字
├ showAbortWarning     中途取消时是否二次确认
├ showDetails          是否显示安装 / 卸载的滚动日志
├ headerImage          内页顶部横版位图（150×57 BMP）
├ welcome       { enabled, title, text, image }        image = 164×314 BMP
├ license       { enabled, source, text, file, requireAccept,
│                 acceptText, textTop, textBottom }
├ changelog     { enabled, source, text, file, title, subtitle }
├ directoryPage { textTop, textDestination }
├ optionsPage   { enabled, title, subtitle, groupText, intro, hint }
└ finish        { title, text, runApp, runText, link{ enabled, text, url } }

    # 协议 / 日志的 source：
    #   "text" = 用 text 字段里直接编辑的正文
    #   "file" = 从 file 指向的 txt 读取
    # 两个字段同时保留，来回切换不丢内容。
    # 老工程没有 source 字段 -> 有 file 就当 "file"，保证照常可用。
    # 内嵌正文写多长都不会被截断（生成器逐行塞进控件，不经过 NSIS 变量）。

shortcuts          # 快捷方式
├ desktop   { enabled, default, userCanToggle, name }
└ startMenu { enabled, default, userCanToggle, name, useFolder, uninstallShortcut }

uninstall          # 怎么卸
├ userDataPath             用户数据目录，如 $APPDATA\{appName}
├ askKeepUserData          卸载时是否询问「是否保留用户数据」
├ keepUserDataText         询问文案
├ deleteUserDataByDefault  静默卸载（/S）时按哪个选项走
└ autoClose                卸载完成后自动关闭窗口

build              # 输出
├ outputDir     安装包输出位置；留空 = 桌面；相对路径按工程文件所在目录解析
├ fileName      文件名模板，如 {appName}-{appVersion}-Setup.exe
├ compression   "solid-lzma" | "lzma" | "zlib" | "bzip2"
└ modes         这次要生成哪些模式；多于一项时文件名自动加 -PerMachine / -PerUser
```

### 3.5 文字里的两种「变量」

| 写法 | 含义 | 例子 |
|---|---|---|
| `{appName}` `{appVersion}` `{appPublisher}` `{appHomepage}` `{appCopyright}` `{installMode}` `{installDirName}` | **打包时**由设计器替换 | `欢迎使用 {appName} 安装向导` |
| `$INSTDIR` `$APPDATA` `$PROGRAMFILES64` … | **安装时**由 NSIS 替换，原样保留 | `安装位置：$INSTDIR` |

转义规则（生成器负责）：
先展开 `{...}`，再把剩下的 `$` 转义成 `$$`，
**但**匹配 `$(INSTDIR|APPDATA|LOCALAPPDATA|PROGRAMFILES64|PROGRAMFILES|SMPROGRAMS|DESKTOP|TEMP|WINDIR)` 的写法保留不转义。
`"` 转义成 `$\"`。

### 3.6 三个文件的编码要求（实测踩坑，必须固化到生成器里）

| 文件 | 编码 | 原因 |
|---|---|---|
| `.nsi` 脚本 | UTF-8 **带 BOM** | 否则脚本里的中文文案乱码 |
| 许可协议 `.txt` | UTF-8 **带 BOM** | MUI 的协议页要求 |
| 更新日志 `.txt` | UTF-16LE **带 BOM** | `FileRead` 不认 UTF-8；必须配 `FileReadUTF16LE` 读 |

设计器应当在用户选择文件时**自动转码**到 `build/` 临时目录，不要要求用户自己存对格式。

### 3.7 派生字段（不存储，由其他字段算出）

这些**不进工程文件**，由生成器现算，避免用户配出互相矛盾的组合：

| 派生值 | 来源 |
|---|---|
| 安装目录名 | `app.dirName`，缺省取 `app.name` |
| `registryKey` | 缺省取 `dirName` |
| `fileVersion` | 缺省把 `version` 补成 `a.b.c.d` |
| 卸载项 `DisplayName` / `DisplayVersion` / `Publisher` / `DisplayIcon` / `InstallLocation` / `UninstallString` | `app.*` + `install.mode` |
| 卸载项 `EstimatedSize` | `${GetSize} $INSTDIR` |
| 注册表根 `HKLM` / `HKCU` | `install.mode` |
| `RequestExecutionLevel` / `SetShellVarContext` | `install.mode` |
| 选项页两个复选框的文案 | `shortcuts.desktop.name` / `shortcuts.startMenu.name`，模板为 `在桌面创建 {name} 的快捷方式(&D)` |
| 快捷方式与「立即运行」的目标 | `$INSTDIR\{app.mainExe}` |
| 卸载页（确认页 + 进度页） | 恒定存在，不需要配置 |

## 四、校验规则

### 必须（阻断打包）

- `formatVersion` 为已知版本
- `app.name` 非空；`app.version` 匹配 `^\d+\.\d+(\.\d+)?(\.\d+)?$`
- `app.name` / `dirName` / `registryKey` 不含 `\ / : * ? " < > |` 和 `$`，不以空格或句点结尾
- `files.items` 至少一项
- **能确定 `app.mainExe`**（显式指定，或在安装目录根部识别到唯一的 `.exe`）
- `files.items[].source` 存在
- 启用的页面所引用的文件都存在（协议、日志、图标、位图）

### 警告：工程目录之外的文件

路径可以写绝对路径，也可以用 `..` 跳出工程目录——这两种都允许，
但会给出**警告**：工程一旦被拷到别的电脑或别的目录，这些引用就失效了。

设计器的做法是：用户选了工程外的文件时，弹窗询问「复制进工程」还是「直接引用」，
默认推荐复制进工程（这样整个工程文件夹可以随意搬移、压缩、发给别人）。

### 尺寸必须精确（MUI 会强校验，提前拦住比让 makensis 报错友好）

| 资源 | 要求 |
|---|---|
| `app.icon` | `.ico` 且**至少包含 256×256 和 16×16** 两个尺寸，32 位色 |
| `interface.welcome.image` | BMP，**164 × 314** |
| `interface.headerImage` | BMP，**150 × 57** |
| 可选：设计器内置生成器提供「一键生成默认图标/位图」，用户不用自己做图 |

### 警告（不阻断，但要在界面上提示）

- `publisher` 或 `copyright` 为空 → exe 属性和卸载项里缺信息
- 更新日志超过约 **1000 字** → NSIS 变量上限会截断（v1 限制；后续可换大字符串版 NSIS）
- 未提供 `icon` → 用默认图标，安装包辨识度低
- `mainExe` 与 `app.name` 毫不相关 → 可能是选错了文件
- 允许 `perMachine` 但未提供 `publisher` → 卸载列表里会显示「未知发布者」，观感差

## 五、与 NSIS 的映射

| `.aiproj` 字段 | 生成的 NSIS |
|---|---|
| `app.name` / `app.version` | `Name` / `!define APP_NAME` / `VIAddVersionKey` |
| `app.dirName` | `InstallDir` 末尾路径段、`registryKey` 默认值 |
| `app.publisher` / `copyright` / `homepage` / `description` | `VIAddVersionKey`（写进 exe 属性）、卸载项 `Publisher` / `URLInfoAbout` |
| `app.icon` | `MUI_ICON` / `MUI_UNICON` / `CreateShortCut` 的图标参数 |
| `app.mainExe` | `MUI_FINISHPAGE_RUN`、快捷方式目标 |
| `install.mode` | `RequestExecutionLevel` + `SetShellVarContext` + `REG_HIVE` |
| `install.defaultDir` | `InstallDir` |
| `install.rememberLastDir` | `InstallDirRegKey` |
| `install.allowChangeDir` | 是否 `!insertmacro MUI_PAGE_DIRECTORY` |
| `install.estimatedSizeAuto` | `${GetSize}` + `EstimatedSize` 注册表值 |
| `interface.brandingText` | `BrandingText` |
| `interface.headerImage` | `MUI_HEADERIMAGE_BITMAP` |
| `interface.welcome.*` | `MUI_WELCOMEPAGE_TITLE` / `_TEXT` / `MUI_WELCOMEFINISHPAGE_BITMAP` |
| `interface.license.*` | `MUI_PAGE_LICENSE` + `MUI_LICENSEPAGE_CHECKBOX*` |
| `interface.changelog.*` | `Page custom` + `nsDialogs`（RichEdit）+ `.onInit` 里 `File /oname=$PLUGINSDIR\...` |
| `interface.directoryPage.*` | `MUI_DIRECTORYPAGE_TEXT_TOP` / `_TEXT_DESTINATION` |
| `interface.optionsPage.*` | `Page custom` + `nsDialogs`（GroupBox + Checkbox） |
| `interface.finish.*` | `MUI_FINISHPAGE_TITLE` / `_TEXT` / `_RUN` / `_LINK` |
| `shortcuts.*` | 选项页复选框默认值 + `CreateShortCut` + 卸载时 `Delete` |
| `uninstall.*` | `un.onInit` 询问 + `Section Uninstall` |
| `files.items[]` | `SetOutPath $INSTDIR\<dest>` + `File /r` |
| `build.*` | `OutFile` / `SetCompressor` |

## 六、版本演进

- **v1 → v2 时**：只增字段不改语义，`formatVersion` 递增；
  读取旧文件时用字段默认值补齐即可（向后兼容）。
- 需要**改语义**时新建字段名（如 `mode2`），旧字段保留只读兼容。
- 任何情况下都不允许「静默丢弃」用户配过的字段——读不懂就报错，不要猜。
